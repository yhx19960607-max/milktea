## 存储方式

每个微信用户在云端对应一条记录，用微信返回的 OpenID 作为唯一标识。用户不直接访问数据库，小程序先把数据传给 `userSync` 云函数，云函数确认用户身份后再读写自己的数据。

| 字段 | 含义 |
|---|---|
| `_id` | 用户 OpenID，用来区分不同用户 |
| `profile` | 用户档案：身高、体重、年龄、性别、活动量 |
| `diary` | 按日期保存饮食记录和运动记录 |
| `profileUpdatedAt` | 档案最近更新时间，用于多设备合并 |
| `diaryUpdatedAt` | 日记最近更新时间，用于多设备合并 |
| `createdAt` | 首次同步时间 |
| `updatedAt` | 最近一次同步时间 |

## 同步逻辑

- 小程序启动后自动获取微信身份并登录。
- 档案、饮食、运动发生变化后自动上传云端。
- 启动或手动同步时会比较本地和云端更新时间，保留较新的一份数据。
- 换手机后，只要登录同一个微信账号，就能拉回档案和记录。

## 权限与隐私

- 数据按 OpenID 隔离，普通用户只能通过云函数访问自己的数据。
- 用户档案属于个人健康相关信息，上线前需要在隐私协议中说明采集目的、存储位置和使用范围。
- 后续如果要导出、删除或匿名化用户数据，应继续通过 `userSync` 云函数扩展，避免小程序端直接访问数据库。
