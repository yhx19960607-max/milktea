# 当前 UI 交互优化建议

更新时间：2026-09-10 11:58

## 交互图

- 当前界面地图见：`docs/ui/当前UI交互图.svg`。
- 图中覆盖当前已注册的 6 个核心页面：档案初始化、首页、每日记录、我的、添加饮食、添加运动、奶茶推荐。

## 当前结构结论

1. 产品主链路已经完整：档案初始化 → 首页看余额 → 添加饮食 / 运动 / 奶茶 → 记录页核对 → 我的页修改档案和查看趋势。
2. 首页的作用清晰，用“今天能不能喝奶茶”回答核心问题，再提供拍餐识别、记录运动和奶茶推荐三个快捷入口。
3. 数据来源、云端同步、官方来源比例已经露出，但缺少一个更直白的“数据可信度”说明，普通用户可能不知道“42 款 / 22 款官方来源”意味着什么。

## 修改建议

### 1. 首页增加「今日状态」

现状只显示余额杯数。建议在余额卡下方增加一句更情绪化的状态：

- 余额充足：今天可以安心喝。
- 余额紧张：建议选小杯或纯茶。
- 超出预算：显示“需要运动约 XX 分钟补回”。

价值：用户不用自己理解热量和杯数换算，能更快决定下一步。

### 2. 首页快捷入口改成「目标导向」

当前入口是“拍餐识别 / 记录运动 / 奶茶推荐”。建议每个入口增加一个结果描述：

- 拍餐识别：先记下这顿。
- 记录运动：增加今天余额。
- 奶茶推荐：选一杯合适的。

价值：降低新用户对功能目的的理解成本。

### 3. 运动页减少初次进入压力

当前进入运动页会自动请求隐私和微信运动授权，还同时展示 Apple 健康桥接、自动同步、手动记录、运动建议。信息量偏大。

建议改为分步引导：

1. 首屏只显示手动记录和「自动同步步数」按钮。
2. 用户点击自动同步后，再请求授权。
3. 授权被拒或 iOS 用户，再展开 Apple 健康桥接说明。

价值：避免未理解授权原因时被弹窗打断，也更符合用户对隐私的预期。

### 4. 拍照识别增加「等待感」和「可信度」

当前识别后有“识别结果不会直接保存”的提示，但没有展示识别置信度或失败后的下一步。

建议：

- 识别中显示预计等待时间和可取消按钮。
- 识别失败时提供三条路径：重试、改用文字输入、手动添加。
- 有低置信结果时标注“需要你确认”，而不是所有结果同等展示。

价值：用户更容易理解为什么需要人工确认，也减少识别失败时的挫败感。

### 5. 奶茶推荐增加「为什么推荐」

当前推荐只显示名称和热量。建议在推荐卡下方增加一句解释：

示例：“今天还剩 760 kcal，这杯最接近且低于预算，选无糖小杯更稳。”

价值：让推荐更像产品建议，而不是数据库排序结果。

### 6. 记录页增加「时间线」

当前记录按饮食和运动分两块。可以保留分组，但为每条记录增加时间段或排序说明：

- 饮食按记录时间排序，标出早 / 午 / 晚 / 夜宵。
- 运动显示开始时间或来源同步时间。

价值：用户回看一天时，更容易回忆自己什么时候吃了什么、做了什么运动。

### 7. 我的页把「云端同步」前置说明收益

当前云同步更偏技术状态。建议改为用户能理解的表达：

- 同步成功：记录已云端备份，换手机也能找回。
- 同步失败：数据还在本机，稍后会重试。
- 立即同步：把当前修改备份到云端。

价值：降低“云函数 / 数据库 / OpenID”这类技术概念带来的理解负担。

## 建议优先级

| 优先级 | 建议 | 理由 |
|---|---|---|
| P0 | 首页今日状态 | 直接服务核心决策 |
| P0 | 拍照识别失败路径 | 当前 OCR 属于核心体验风险点 |
| P1 | 运动授权分步引导 | 减少流失和隐私焦虑 |
| P1 | 奶茶推荐解释 | 提升推荐可信度 |
| P2 | 记录时间线 | 增强回看能力 |
| P2 | 云同步用户化表达 | 提升数据安全感 |
